# Code Review — T-10b (read-only)

Scope: 4 bonding Kotlin files, 2 app Kotlin files, 4 node files.
Method: manual read only; no gradle, no fixes.

## BLOCKER
- app/app/src/main/java/com/wearless/app/vpn/TunnelService.kt:120 — the TUN interface is created with Builder().establish() and the returned ParcelFileDescriptor is discarded, and no VpnService.protect()/addDisallowedApplication() is applied to the bonding engine's sockets — the tunnel routes 0.0.0.0/0 into itself, so mqvpn's own UDP 443 packets loop back into the TUN and the fd can be closed by GC at any time — fix: hold the ParcelFileDescriptor in a field, call protect(fd) on every engine socket (or addDisallowedApplication for the engine process), add an explicit MTU, and close the fd in stopTunnel().
- node/install.sh:151 — the iptables fallback branch inserts INPUT ACCEPT rules for 443/udp (and ip6tables) at install time but never persists them (no iptables-save, no netfilter-persistent, no unit) — after a reboot the node restarts via systemd while the firewall rule is gone, so clients silently cannot reach UDP 443 — fix: after inserting, persist via `netfilter-persistent save` if available, else write a small oneshot unit that restores the rules, and fail the install when no persistence path exists.

## MAJOR
- app/app/src/main/java/com/wearless/app/vpn/TunnelService.kt:97 — startTunnel() is not idempotent: every onStartCommand (including START_STICKY redelivery with a null intent) and every watchdog restart calls Builder().establish() again and startWatchdog() again, leaking TUN fds and replacing the watchdog without closing the old one — fix: return early when a session/fd already exists, keep a single watchdog job, and tear down the old TUN before re-establishing.
- app/app/src/main/java/com/wearless/app/vpn/TunnelService.kt:115 — BondingBridge.start(cfg.serverAddress, cfg.keyRef, true, links) hardcodes the third argument and never passes BondingConfig/SchedulerPolicy output, so the selected scheduler and reorder-buffer decision are never applied to the live engine — fix: load the full BondingConfig from NodeConfigStore and pass scheduler/reorderBuffer (or the PreparedSession) through, instead of a literal true.
- app/app/src/main/java/com/wearless/app/vpn/TunnelService.kt:137 — the watchdog restarts the tunnel every 5s forever when the engine keeps failing (no backoff, no retry cap, no distinction between "died" and "cannot start") and re-triggers requestBatteryExemptionIfNeeded() each pass — fix: add exponential backoff with a cap, surface a terminal Failed state after N attempts, and request battery exemption once per user action, not per restart.
- node/wearless-node.service:13 — ExecStart passes `--mode server --config ...` to /usr/local/bin/mqvpn, a CLI whose flags were never verified (install.sh still ships the "TO VERIFY" URL), so a wrong flag combination crash-loops the unit while the installer reports success — fix: verify the server invocation against the pinned mqvpn build and add an ExecStartPre check (or a `--version`/`--help` probe) so a bad binary fails the install loudly.
- app/app/src/main/java/com/wearless/app/MainActivity.kt:64 — after stopService() the activity immediately calls renderStopped(), showing "stopped" and NOT MEASURED before TunnelService has actually torn down the tunnel, so the UI can claim stopped while bonding is still up — fix: drive the UI only from BondingBridge.state (renderState() on state change) and remove the optimistic renderStopped() call.

## MINOR
- app/bonding/src/main/kotlin/com/wearless/bonding/StatsAggregator.kt:72 — aggregatedBps sums rxBps + txBps across links and stays non-zero even when the snapshot is flagged isMeasured=false, so "aggregated speed" silently means something different from the per-link rxBps shown in the UI — fix: define aggregatedBps as the sum of a single named direction (or document it as total throughput) and zero it when isMeasured is false.
- app/bonding/src/main/kotlin/com/wearless/bonding/MqvpnEngineAdapter.kt:98 — the literal token `${keyRef:...}` is injected into argv with no validation that the platform substitution will ever happen; if it is forgotten, mqvpn receives a bogus key-file path — fix: validate the token shape at prepare time and fail with InvalidConfig when keyRef does not look like a reference.
- app/bonding/src/main/kotlin/com/wearless/bonding/MqvpnEngineAdapter.kt:105 — flags are built by String.split(" ") over constants and `--bind-interface <id>` is repeated per link, a shape that is explicitly TO VERIFY; a per-link list or a comma-joined value would also break — fix: replace split(" ") with explicit List<String> constants and pin the bind-interface syntax against the installed engine.
- app/bonding/src/main/kotlin/com/wearless/bonding/MqvpnEngineAdapter.kt:140 — notMeasuredSnapshot() hardcodes active = true for every link, so an unmeasured link is rendered as "on" in the UI despite the honest-data contract — fix: pass the real LinkHandle state (or active = false) through.
- app/bonding/src/main/kotlin/com/wearless/bonding/FailoverMachine.kt:59 — once the machine reaches ALL_LINKS_LOST, onLinkUp() deliberately refuses to leave that state, so a session whose links all come back stays permanently dead until an external restart — fix: allow an explicit recover()/restart transition and document who calls it.
- app/app/src/main/java/com/wearless/app/MainActivity.kt:130 — `snap.aggregatedBps != null` is always true because aggregatedBps is a non-null Long, a dead condition that reads like a null guard — fix: drop the null check and rely on snap.isMeasured.
- node/control.sh:50 — check_response() only detects the literal `"ok": false`; any other error shape (error/message-only replies) passes as success — fix: also treat missing `"ok":true`, an `error` key, or an empty response as failure.

## NIT
- app/bonding/src/main/kotlin/com/wearless/bonding/SchedulerPolicy.kt:56 — reorderBufferRecommended(scheduler) ignores its parameter (suppressed as UNUSED_PARAMETER) and always returns true, making the scheduler argument misleading — fix: drop the parameter or make the answer scheduler-dependent.
- app/app/src/main/java/com/wearless/app/MainActivity.kt:110 — launchTunnelService() creates a CoroutineScope(Dispatchers.Main) that is never cancelled, one per start — fix: use a lifecycle-scoped viewModelScope/lifecycleScope.
- app/app/src/main/java/com/wearless/app/vpn/TunnelService.kt:87 — the API level is compared to the magic number 34 — fix: use Build.VERSION_CODES.UPSIDE_DOWN_CAKE.
- node/install.sh:128 — the download branch compares against the sentinel string "TO VERIFY — official release URL" (with an em dash), which breaks silently if the text is ever edited — fix: use a separate MQVPN_URL_SET flag or an empty default.
- node/wearless-node.service:20 — the unit is well hardened but lacks ProtectProc, RestrictAddressFamilies, and a SystemCallFilter — fix: add ProtectProc=invisible, RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6 AF_NETLINK, and a SystemCallFilter=@system-service set.
- node/control.sh:4 — CONTROL_HOST/CONTROL_PORT are hardcoded with no environment override, unlike stats.sh — fix: allow WEARLESS_CONTROL_HOST/WEARLESS_CONTROL_PORT overrides.
